Selenium 框架实现

Selenium 没有内置的 API 客户端，需要手动将认证凭证注入浏览器，主要有两种途径。

方法一：通过 Cookie / LocalStorage 注入

如果 Token 存储在 Cookie 或 LocalStorage 中，可以直接注入。

方法二：通过自定义请求头（不支持直接设置）

方法三：通过 Chrome DevTools Protocol (CDP) 设置请求头（进阶）

这是相对现代且更干净的方式，绕过代理直接通过 CDP 设置请求头。

这种方法直接通过 Chrome DevTools Protocol（CDP）拦截并修改网络请求，是目前 Selenium 中最灵活且最接近”原生”的做法。

总结

框架 推荐方案 适用场景
Playwright context.request + storageState 组合 首选的”丝滑”体验，强烈推荐
Playwright page.route 拦截并修改请求 Token 放在 Header 中（如 JWT）
Selenium Cookie / LocalStorage 注入 Token 存储在 Cookie 或 LocalStorage 中
Selenium CDP 方法（execute_cdp_cmd） Token 放在 Header 中，推荐使用
Selenium 代理方案 无法使用 CDP 时的备选方案

通过后端接口认证可以显著提升自动化测试的效率，避免重复的登录操作和验证码处理。根据项目使用的框架选择合适的实现方式，可以让测试更加稳定和高效。
